# 浏览器活动历史采集审查（2026-09-17）

本次未请求任何真实模型 API。Codex 对照实际采样、网页正文、系统焦点和四类窗口截图进行了阅读检查；这不是盲测模型成绩。

有效回归运行：`artifacts/dshmonitor-test-pack/20260917-161430-600994/browser-history-capture/`。独立 Xvfb/Openbox 桌面、真实 Chromium、真实 BrowserSkill 扩展，运行生产 Collector、timeline、apply_time_patch 和 export_request。真实采集 28.51 秒，52 个样本、60 条语义快照；映射为 600 秒。测试浏览器及桌面已清理。

| 模拟计划时间 | 从保存材料看到的情况 | 对照结论 |
|---|---|---|
| 0–120 秒 | 事务笔记获得焦点；正文有“提交标记：青松”，截图显示提交段落 | 能确认页面内容与显示段落，不能证明人理解了它 |
| 120–240 秒 | 仍是事务笔记；截图从提交段落变为回滚段落，显示“回滚标记：白鹭” | 可以借截图确认滚动后的可见内容；仅语义文本不够 |
| 240–340 秒 | 娱乐页有“收集七颗星星”“四十二分”；焦点时间轴约 240.05–354.15 秒指向方块乐园 | 能还原娱乐阶段；切换边缘存在采样延迟 |
| 340–480 秒 | 系统焦点约 354.15 秒切到数据库术语速查；正文包含原子性、一致性和“银杏” | 能还原查资料。后台娱乐页仍有语义快照，不能算持续游玩 |
| 480–600 秒 | 焦点约 491.65 秒回到事务笔记，窗口截图显示回滚段落 | 能还原返回论文，边缘时间不是精确点击时间 |

实际存在的限制：

1. BrowserSkill 语义快照把提交、回滚两段都提取出来，即使只有一段在视口内。需要结合历史截图，不可从正文直接推断阅读范围。
2. 浏览器窗口 ID 和系统窗口 ID 尚未可靠连接。此次页面标题不同，人工可以交叉核对；同名多窗口、改标题、多个 profile 的歧义未覆盖。
3. 独立桌面里的娱乐结束边界相差约 14 秒模拟时间（约不到 1 秒真实时间），不能声称秒级准确。
4. 本用例采样和截图间隔缩短了，不能直接证明生产的 10 秒正文采集频率能捕获更短的切换。
5. 默认概览把多个页面归为一个浏览器程序，必须继续读时间轴和浏览器分支，不能仅靠程序总时长判断。
6. 未覆盖短暂闪过的页面、相同标题标签页、登录限制、PDF/canvas、跨域 iframe、大量窗口和浏览器崩溃。测试中的娱乐页是另一个后台窗口的选中页，尚未覆盖同一窗口中的非选中后台标签页。

本机 GNOME 补充运行：`artifacts/dshmonitor-test-pack/20260917-160601-723364/browser-history-capture/`。真实正文和窗口截图均采到，但 `driver_observation` 显示部分 `window.focus()` 请求没有真正取得页面焦点，不能将其当成已成功模拟返回工作的验收。该记录保留为实际桌面边界，不用独立 X11 结果替代 GNOME 验收。

后续回归：运行 `run.py test --case browser-history-capture`。每阶段缺少正文或焦点证据将返回失败；即使通过，也只表示这组场景的采集回归通过，不表示真实 AI 的理解能力或所有桌面环境均已验证。
